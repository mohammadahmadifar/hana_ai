  1. ۱

  2. ۲

  3. ۳

    مسیر ویندوزی هاردکد بود. در دو فایل، tesseract_cmd مستقیم روی C:\Program Files\… ست شده بود؛ روی لینوکس بلافاصله خطا می‌داد. حالا در settings.py حل می‌شود: ویندوز همان مسیر، لینوکس و مک از PATH، و در هر دو با متغیر محیطی TESSERACT_CMD قابل بازنویسی.

linux / wsl

# پیش‌نیاز سیستمی
sudo apt install tesseract-ocr \
     tesseract-ocr-fas tesseract-ocr-eng \
     python3-venv

# پروژه
git clone git@github.com:mohammadahmadifar/hana_ai.git
cd hana_ai
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt

# اجرا — حتماً از ریشهٔ پروژه
.venv/bin/python main.py

windows

# Tesseract را از UB-Mannheim نصب کن
# و در نصب، Persian را تیک بزن:
# github.com/UB-Mannheim/tesseract/wiki

python -m venv .venv
.venv\Scripts\pip install -r requirements.txt

# اگر جای دیگری نصب شد:
set TESSERACT_CMD=D:\Tesseract\tesseract.exe

.venv\Scripts\python main.py

مسیرهای پروژه نسبی‌اند، پس main.py باید از ریشهٔ مخزن اجرا شود. خروجی‌ها در dataset/ ساخته می‌شوند و همگی در .gitignore هستند — یعنی هر بار از صفر قابل بازتولیدند.

یافته‌ها

دو تا از این‌ها باگ منطقی‌اند — یعنی حتی اگر OCR بی‌نقص کار کند هم عدد صفر می‌ماند. بقیه مسئلهٔ کیفیت تصویر یا معیار سنجش‌اند.

  1. باگ منطقی

    پلاک هرگز نمی‌تواند درست شمرده شود

    لیبل پلاک را به شکل «۱۰ ۶۴۳ ج ۷۶» می‌سازد (دو رقم، سه رقم، حرف، دو رقم) ولی format_plate خروجی OCR را به شکل «۱۰ ج ۶۴۳ ۷۶» می‌چیند. ترتیب حرف و عدد وسط جابه‌جاست، پس مقایسه در هر حالتی رد می‌شود — دقت ۰٪ این فیلد ربطی به کیفیت OCR ندارد.

    app/person/person_generator.py:generate_plate_number ↔ app/ocr/vehicle_card_ocr.py:format_plate

    جدا از این، سگمنت‌کردن پلاک هم واقعاً کار نمی‌کند: تعداد تکه‌ها بین ۸ تا ۱۳ نوسان دارد و نقطهٔ حروف به‌عنوان کاراکتر جدا خوانده می‌شود.

    پیشنهاد: اول قالب هر دو طرف را یکی کن (ترجیحاً قالب واقعی «۱۲ ب ۳۴۵ ایران ۶۷»)، بعد سراغ بهبود سگمنتیشن برو. تا وقتی قالب‌ها یکی نشده‌اند، هر بهبودی در OCR در عدد دیده نمی‌شود.

  2. ۰٪

    نام روی گواهینامه اصلاً خوانده نمی‌شود

    در هر ۱۵ نمونه، فیلد «نام و نام خانوادگی» گواهینامه رد شد؛ Tesseract جای آن چیزهایی مثل «ح ۹ ۶» برمی‌گرداند. مشکل از OCR فارسی نیست — همان نام روی کارت ملی ۹۳٪ و ۱۰۰٪ خوانده می‌شود. نام روی گواهینامه روی یک ناحیهٔ گرادیانِ روشن و کم‌کنتراست چاپ می‌شود و بعد از خاکستری‌سازی تقریباً در پس‌زمینه حل می‌شود.

    dataset/image_writer.py:create_driving_license — draw at x=1100, y=480

    پیشنهاد: یا محل چاپ نام را به ناحیهٔ روشن‌ترِ کارت ببر، یا در پیش‌پردازش به‌جای خاکستری سادهٔ کل تصویر، آستانه‌گذاری تطبیقی (adaptiveThreshold) بگذار تا متن از پس‌زمینهٔ گرادیانی جدا شود.

  3. معیار

    VIN اغلب درست خوانده می‌شود ولی به‌خاطر یک فاصله رد می‌شود

    نمونهٔ واقعی: لیبل NAS549312M4173578 و خروجی OCR NAS549319M44 73578. یک فاصلهٔ اضافه وسط رشته کافی است تا مقایسهٔ «آیا لیبل داخل متن هست» رد شود. تابع مقایسه برای فیلدهای نام فاصله‌ها را حذف می‌کند ولی برای VIN و کد ملی نه.

    app/evaluation/ocr_evaluation.py:compare_fields — شاخهٔ else

    پیشنهاد: برای فیلدهای کاملاً عددی/الفبایی‌عددی (کد ملی، VIN، شماره گواهینامه) هم قبل از مقایسه فاصله‌ها حذف شوند. کم‌هزینه‌ترین تغییری است که عدد را جابه‌جا می‌کند.

  4. کیفیت ورودی

    قالب کارت ملی نصفِ بقیه رزولوشن دارد

    قالب کارت ملی ۹۶۰×۵۴۰ است در برابر ۱۵۳۷×۱۰۲۳ گواهینامه، و فونتش ۳۲ در برابر ۳۸. نتیجه‌اش مستقیم در عدد دیده می‌شود: کد ملی روی کارت ملی ۴۷٪، روی گواهینامه ۸۷٪ — همان فیلد، همان موتور، فقط اندازهٔ متفاوت. تاریخ‌های کارت ملی هم به همین دلیل ۳۳٪ و ۴۰٪ ماندند.

    dataset/templates/national_card.png (960×540)

    پیشنهاد: قالب بزرگ‌تر بگذار، یا در پیش‌پردازش تصاویر کوچک را قبل از OCR دو برابر کن. Tesseract زیر حدود ۳۰ پیکسل ارتفاعِ متن به‌سرعت افت می‌کند.

  5. پیش‌پردازش

    چرخش جبران نمی‌شود

    چرخش با میانگین ۴۴.۹٪ بدترین اعوجاج است، در حالی که نویز ۷۶.۷٪ می‌گیرد. مرحلهٔ پیش‌پردازش سه کار می‌کند — خاکستری، حذف نویز، شارپ — و هیچ‌کدام زاویه را برنمی‌گردانند. یعنی دقیقاً آن خرابی‌ای که بیشترین آسیب را می‌زند، هیچ پادزهری ندارد.

    app/preprocessing/image_preprocessing.py:preprocess_image

    پیشنهاد: یک مرحلهٔ deskew اضافه کن (زاویه را با minAreaRect روی ماسک متن یا با تبدیل هاف تخمین بزن و برگردان). به‌احتمال زیاد بیشترین جهش عدد از همین یک تغییر می‌آید.

  6. معیار

    سنجش «درست یا غلط» است، نه «چقدر نزدیک»

    معیار فعلی زیررشته‌ای است: یک کاراکتر اشتباه در تاریخ ده‌کاراکتری، کل فیلد را صفر می‌کند. برای یک پایان‌نامه این عدد هم بدبینانه است و هم اطلاعاتی به دست نمی‌دهد — نمی‌شود فهمید بهبود پیش‌پردازش واقعاً اثر داشته یا نه.

    app/evaluation/ocr_evaluation.py:compare_fields

    پیشنهاد: کنار همین معیار، نرخ خطای کاراکتری (CER بر پایهٔ فاصلهٔ لِوِنشتاین) هم گزارش شود. هم عدد واقع‌بینانه‌تری می‌دهد، هم در متن پایان‌نامه معیار استانداردتری است.

  7. جزئی

    هر اجرا کل تصاویر قبلی را دوباره پردازش می‌کند

    main.py هر بار فقط یک شخص می‌سازد (number = 1) ولی مراحل ۴ تا ۶ روی تمام محتویات پوشه‌ها اجرا می‌شوند. یعنی برای رسیدن به ۵۰ نمونه، اجرای پنجاهم پنجاه تصویر را دوباره OCR می‌کند. برای ساخت دیتاست بزرگ، number را بالا ببر به‌جای اجرای مکرر.

    main.py

  8. جزئی

    ماژول کارت خودرو موقع import کار جانبی می‌کند
